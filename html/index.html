hako 箱 · hako-code · the agent

— II — agent  ·  v0.3.0 · stable

A coding agent in one C file — a ~650 KB binary that links libc and nothing else. No Python, no Node, no package manager. Defaults to any installed hako model (hako-sho 3B / hako-koi 7B) — no key, no cloud — and adds 14 cloud providers when you want them. hako --serve puts the same agent in a browser tab; the page is compiled into the binary.

— Code search built in (grep · glob · web_fetch) · diffs before it writes · context that folds instead of running out · skills you can switch on as modes · streaming on every provider · trust-gated tools · sha-verified self-update.

Install

# the agent
curl -fsSL https://mithraeums.github.io/hako.sh | sh

# the editor
curl -fsSL https://mithraeums.github.io/hake.sh | sh

# the engine — build from source (libc + libm + pthread only)
git clone https://github.com/mithraeums/hako && cd hako && make

Each installer fetches the latest signed release for your OS/arch, verifies the sha256 sidecar, drops the binary in ~/.local/bin. No package manager, no daemon, no telemetry.

Skills — behaviors for hako, by name

Each is a folder in mithraeums/skills: a SKILL.md plus helpers. Markdown only — works in hako and in Claude.

  • 01 corp/ — A company in a folder. CEO · DEV · DESIGN · QA · ARCH — routes tasks by domain. Ships as CLAUDE.md + AGENTS.md, molds to its host.
  • 02 brief/ — Token-lean output. Cut ~50–75% of length, keep every fact. Drops filler, not information.
  • 03 memory/ — Durable cross-session memory: a MEMORY.md index + one-fact-per-file, with recall & dedupe rules. No database.
  • 04 sync/ — Change once, update everywhere — docs, version strings, sibling repos, JSON. Kills the "did I get them all?" miss.
  • 05 scope/ — Vague ask → goal + explicit non-goals + smallest viable step, before building. Stops scope creep.
  • 06 release/ — Bump version consistently, write the changelog, generate a multi-repo push-order checklist.
  • 07 handoff/ — Write a START-HERE state doc (done / next / gotchas) so the next session resumes in seconds.
  • 08 changelog/ — Turn a diff or session log into one clean CHANGELOG entry, in the project’s own voice. Single-repo; the focused half of release.
  • 09 debug/ — Find the real cause before touching code: read the evidence, reproduce, shrink, then fix with a test that fails on the old code.
  • 10 gitflow/ — A reviewed push flow for agent-written code: check · push · merge · tag, y/N at every step, commits under your name only.
  • 11 ship/ — The pre-push gate: build matrix · sanitizers · version-drift · CHANGELOG sync · cruft · docs. Returns PASS or BLOCKED, never a vibe.
  • ·· your skill here — open a PR; the folder name becomes the invocation.

hako-code v0.2.4 · 2026-09-21

it runs where nothing else does

Three weeks on an iPhone and an iPad under iSh &mdash; where Claude Code, Hermes and Codex would not install &mdash; and on a desktop, inside itself, with Claude driving. What that found was a class of bug, not a list: failures that were silent by construction. A backslash landing on a network chunk boundary deleted the chunk. A line longer than the read buffer was quietly cut. An Anthropic overload came back as &ldquo;empty response&rdquo;. A tool call with only a closing tag ended the turn with nothing shown. A 100&nbsp;KB file was truncated without a word and the model rewrote it from the half it saw. A freeze after a successful edit was two readers on one keyboard. Every one is gone, and each has a test. Underneath: the input bar lives in the flow of the terminal &mdash; no absolute cursor moves, no scroll region &mdash; so a phone keyboard appearing no longer duplicates the conversation; type while it works and it queues; ctrl+o is a transcript pager. Local models stream, and the engine keeps its prefilled prompt on disk: a cold first turn on a 3B model went from four minutes to two seconds. grep/glob/web_fetch, context compaction, skills on demand, a diff before every approval, prompt caching, --bench. And you can finally see what happened: the session log carries every system notice, --debug writes a startup trace, and a dead engine reports its own last words.

hako engine v0.0.4 · 2026-09-21

streams · remembers · stays bounded

--serve sends each token as it is sampled, so the agent types a local answer out in real time. The prefilled system prompt persists on disk and comes back on the next run &mdash; 255&nbsp;s to 2.3&nbsp;s for a cold first turn on a CPU-only i3 &mdash; and that cache is now bounded: one file per distinct prompt had piled up 359&nbsp;MB before anyone looked, and the device this has to behave on is a phone. A heap overflow waiting for the first small model is fixed and pinned under ASan. Builds on musl and 32-bit x86 (no -march=native under an emulator that advertises instructions it cannot run). hakm list | pull | rm, llama-arch models, Q8_0. Still libc + libm + pthread.

hako studio — the agent in a browser tab

hako --serve opens the same agent in a browser: chat, tool-approval boxes, a folder browser, per-folder sessions you can rename and delete, the model picker, four themes. hako engine v0.0.3 · 2026-07-18

faster prefill · steady under pressure

The Q4_K prefill kernel drops half its per-group MACs: the min term is activation-only, so scale·Σx is folded once per activation and reused across every weight row — ~1.3× prefill on a CPU-only i3, greedy output bit-identical (a make test_kdot proves it against a scalar reference). A repetition penalty joins the sampler (--rep, default off so tool turns stay deterministic), and hakm_ctx_new now guards its allocations and fails clean instead of segfaulting when RAM runs short. Still libc + libm + pthread, no llama.cpp, no ollama.
